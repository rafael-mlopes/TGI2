Integração Telemetria MQTT x ERP

1. Visão Geral

Este projeto é o motor de integração bidirecional responsável por conectar as máquinas do chão de fábrica (via protocolo MQTT) ao sistema ERP (banco Firebird). Ele atua recebendo dados de telemetria (velocidade, OEE, produção) em tempo real e enviando ocorrências e ordens geradas no ERP para as máquinas.

Pré-requisitos Técnicos:

  • Ambiente: Python 3.x (compilado via PyInstaller ou execução direta).
  • Bibliotecas: paho-mqtt, fdb (Firebird), flask, waitress, flasgger.
  • Bancos de Dados: Dois bancos Firebird distintos (Client/ERP e Banco Dedicado MQTT).
  • Arquivo de Configuração: O sistema exige a presença do arquivo GRP.cfg no diretório raiz contendo o alias [MENDES_ZERADO] para montar as connection strings de forma segura.

2. Arquitetura e Módulos

A arquitetura foi desenhada de forma modular, dividindo as responsabilidades de rede (MQTT), processamento de regras de negócio e camada de visualização em 4 scripts principais:

2.1. Motor de Rede: RajBootCLP.py (Transceiver)

Responsável exclusivo por gerenciar os sockets MQTT. Ele assina o tópico principal, escuta o payload das máquinas e realiza inserções brutas na fila do banco de dados (CLP_MMSGREC). Também possui um loop ativo que consome a fila de envio (CLP_MMSGENV) e despacha ordens para o broker MQTT.

2.2. Motor de Negócio: RajBootInter.py (Interpretador)

Atua como a ponte de dados. Realiza o parsing dos arquivos JSON brutos e atualiza o estado atual da máquina (CLP_MACOMP) e o histórico de produção. Paralelamente, rastreia novas falhas/ocorrências lendo a tabela AG_MOCOR no ERP e as formata para entrar na fila de envio do Transceiver.

2.3. Camada de Dados: LibDB.py (Gerenciador)

Biblioteca de abstração do Firebird. Concentra todas as queries, pool de conexões (limite lógico de 1000 usos), rotinas de log do sistema e o controle rigoroso de concorrência (Semáforo) para evitar processos zumbis ou deadlocks na base.

2.4. API Web: LibFlask.py

Servidor REST embutido utilizando Waitress. Expõe os dados de telemetria já consolidados para consumo em dashboards ou interfaces externas. Prioriza a leitura da Memória RAM (Cache do Interpretador) para garantir resposta ultrarrápida, consultando o banco de dados via fallback apenas quando necessário.

3. Configuração de Variáveis (GRP.cfg)

Abaixo está um exemplo da estrutura JSON esperada dentro do arquivo de configuração GRP.cfg para que a comunicação inicie corretamente.

[MENDES_ZERADO]
CLPJS={"dbClient": {"hDB": "localhost", "db": "C:/Bancos/ERP.FDB", "uDB": "SYSDBA", "pDB": "masterkey"}, "dbMqtt": {"hDB": "localhost", "db": "C:/Bancos/MQTT.FDB", "uDB": "SYSDBA", "pDB": "masterkey"}, "Mqtt": {"user": "admin", "pass": "senha123", "broker": "192.168.0.100", "port": 1883, "topic": "Raj/BR_SP/Planta1/#"}, "LogDetalhado": true}
⚠️ Atenção: O parser JSON implementado nativamente converte aspas simples em duplas e escapa barras. Certifique-se de manter o CLPJS= em linha única no ambiente de produção.

4. Dicionário de Dados e Tabelas

💡 Controle de Concorrência: A tabela CLP_MSEMAF é o coração do controle do sistema. Se o sistema cair bruscamente, o mecanismo interno detectará o processo zumbi (após 30 minutos) e o "enterrará" automaticamente, garantindo que as filas voltem a fluir sem intervenção manual.

4.1. Banco de Dados Client (ERP)

Este banco opera em modo Somente Leitura pelo integrador.

Tabela Operação Responsabilidade no Fluxo
AG_MOCOR SELECT Registro bruto de ocorrências e paradas da fábrica. É rastreada em busca de eventos novos.
AG_MTARC / AG_MTAR LEFT JOIN Tabelas relacionais lidas para montar o identificador único do Job (Empresa, Pedido, Item, Máquina).

4.2. Banco de Dados MQTT (Motor Central)

Base dedicada à integração. Processa filas brutas e o estado calculado da telemetria.

Tabela Operação Responsabilidade no Fluxo
CLP_MMSGREC / RECT INSERT / DELETE Fila de Entrada: Recebe metadados e o JSON bruto da máquina. Sofre purge (deleção) ao ser lida.
CLP_MMSGRECL INSERT Sinalização: Histórico de leitura concluída pelo Interpretador. Libera exclusão na fila de entrada.
CLP_MACOMP UPDATE OR INSERT Estado Real-Time: Mantém apenas a foto atualizada do OEE, ciclos e velocidades por Job/Máquina.
CLP_MACOMPH INSERT Histórico: Acumula todos os pacotes de telemetria decodificados ao longo do tempo.
CLP_MMSGENV / ENVT INSERT / UPDATE Fila de Saída: Recebe ordens do Interpretador e é despachada para o Broker pelo Transceiver.
CLP_CEQP SELECT Cadastro: Carrega os IDs em RAM das máquinas ativas na planta para filtro de tópicos.
